## Лабораторная 2. Каталог товаров

Выполнены обязательные задачи 1–6 и дополнительные задачи 7–8.
Продвинутые задачи 9–10 не выполнялись.
[Условие](https://git.digital.mephi.ru/Backend/Project/src/commit/7d0ee186c73d8ab39677218c066f06083296df04/Part-2/README.md).

Приложение на FastAPI работает с категориями, товарами и отзывами.
Данные хранятся в трёх словарях по UUID и исчезают при перезапуске.
Сервер первой работы остался в `lab1/rawhttp/` и запускается отдельно.

## Предметная модель

```text
┌──────────────────┐       ┌────────────────────┐       ┌───────────────────┐
│ Category         │       │ Product            │       │ Review            │
│ id: UUID         │ 1   N │ id: UUID           │ 1   N │ id: UUID          │
│ name             ├───────┤ category_id: UUID  ├───────┤ product_id: UUID  │
│ description      │       │ seller_id: UUID    │       │ user_id: UUID     │
└──────────────────┘       │ name, condition    │       │ rating, text      │
                           │ price              │       └───────────────────┘
                           │ discount_price     │
                           │ stock              │
                           └────────────────────┘
```

В категории может быть несколько товаров, у товара — несколько отзывов.
`category_id` и `product_id` должны ссылаться на существующие записи.
Нельзя удалить категорию с товарами или товар с отзывами: ответ `409`.
Сначала нужно удалить дочерние записи.

Сервер генерирует `id` и подставляет владельца:
`seller_id` товара и `user_id` отзыва равны
`00000000-0000-0000-0000-000000000001`. Это заглушка, авторизации пока нет.

## Запуск

Нужны Git и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Команды выполняются из корня репозитория:

```bash
git switch lab-02
uv sync --locked
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Версия Python 3.13 указана в `.python-version`; uv установит её при необходимости.
Swagger: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
OpenAPI: [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json).
Остановка — `Ctrl+C`. Запускать нужно один процесс: словари не общие между workers.

Начать можно с создания категории:

```bash
curl -i http://127.0.0.1:8000/health
curl -i -X POST http://127.0.0.1:8000/api/v1/categories \
  -H 'Content-Type: application/json' \
  -d '{"name":"Книги","description":"Учебная литература"}'
```

Полученный `id` категории используется при создании товара, а `id` товара — отзыва.
Полные примеры с результатами находятся в [отчёте](docs/lab-02-report.md).

## Карта маршрутов

| Метод | Путь | Смысл | Успех | Ошибки |
|---|---|---|---|---|
| GET | `/health` | Состояние сервиса | 200 | — |
| GET | `/api/v1/categories` | Все категории | 200 | — |
| POST | `/api/v1/categories` | Создание категории | 201 | 422 |
| GET | `/api/v1/categories/{category_id}` | Одна категория | 200 | 404, 422 |
| PUT | `/api/v1/categories/{category_id}` | Полная замена категории | 200 | 404, 422 |
| PATCH | `/api/v1/categories/{category_id}` | Изменение части полей категории | 200 | 404, 422 |
| DELETE | `/api/v1/categories/{category_id}` | Удаление категории | 204 | 404, 409, 422 |
| GET | `/api/v1/products` | Поиск и страница товаров | 200 | 422 |
| POST | `/api/v1/products` | Создание товара | 201 | 404, 422 |
| GET | `/api/v1/products/{product_id}` | Один товар | 200 | 404, 422 |
| PUT | `/api/v1/products/{product_id}` | Полная замена товара | 200 | 404, 422 |
| DELETE | `/api/v1/products/{product_id}` | Удаление товара | 204 | 404, 409, 422 |
| GET | `/api/v1/reviews` | Все отзывы | 200 | — |
| POST | `/api/v1/reviews` | Создание отзыва | 201 | 404, 422 |
| GET | `/api/v1/reviews/{review_id}` | Один отзыв | 200 | 404, 422 |
| PUT | `/api/v1/reviews/{review_id}` | Полная замена отзыва | 200 | 404, 422 |
| PATCH | `/api/v1/reviews/{review_id}` | Изменение части полей отзыва | 200 | 404, 422 |
| DELETE | `/api/v1/reviews/{review_id}` | Удаление отзыва | 204 | 404, 422 |

Для всех путей неподдерживаемый метод даёт `405` с заголовком `Allow`.
Неизвестный путь даёт `404`. Каждый POST возвращает `Location`, DELETE — пустое тело.

## Схемы и правила

Для каждой сущности есть отдельные схемы Create, Replace и Read.
Replace наследует Create, потому что доступные поля и их ограничения совпадают.
Read перечисляет поля явно. Все входные схемы запрещают лишние поля.

| Сущность | Поля, которые может передать клиент |
|---|---|
| Category | `name`: 1–80 символов; `description`: до 500 символов или null |
| Product | `category_id`: UUID; `name`: 1–100 символов; `price`: больше 0; `discount_price`: от 0 или null; `stock`: целое от 0; `condition`: new или used |
| Review | `product_id`: UUID; `rating`: целое 1–5; `text`: до 1000 символов или null |

Название очищается от крайних пробелов и не может состоять только из них.
Цена со скидкой не может быть выше обычной цены — это проверяет валидатор модели.
Все цены указаны в рублях, значения NaN и Infinity запрещены.

PUT заменяет все доступные поля. Обязательные поля должны присутствовать;
пропущенные необязательные получают исходные значения: описания, текст и скидка —
`null`, состояние товара — `new`. Идентификатор и владелец сохраняются.

PATCH есть у Category и Review. Непереданные поля сохраняются, поскольку применяется
`model_dump(exclude_unset=True)`. Явный `null` очищает только `description` или `text`.
Для `name`, `product_id` и `rating` он запрещён. Пустой объект `{}` ничего не меняет.

## Список товаров

| Параметр | Допустимые значения | По умолчанию |
|---|---|---|
| `limit` | целое 1–100 | 20 |
| `offset` | целое от 0 | 0 |
| `condition` | new, used | без фильтра |
| `min_price` | число от 0, нижняя граница цены включительно | без границы |
| `max_price` | число от 0, верхняя граница цены включительно | без границы |
| `sort_by` | name, price, stock | name |

Сначала применяются фильтры, затем сортировка по возрастанию и пагинация.
Фильтр цены использует обычную цену `price`. Если нижняя граница выше верхней,
подходящих товаров нет. Сортировка при одинаковом ключе сохраняет порядок создания.

```bash
curl -i 'http://127.0.0.1:8000/api/v1/products?condition=new&min_price=100&max_price=2000&sort_by=price&limit=2&offset=0'
```

## Ошибки

Обработчики `RequestValidationError` и `StarletteHTTPException` используют одну функцию
формирования ответа. Верхний уровень всегда один и тот же:

```json
{"error":{"code":"validation_error","message":"Запрос не прошёл проверку","details":[{"field":"query.limit","rule":"greater_than_equal","message":"Input should be greater than or equal to 1"}]}}
```

Для 404, 405 и 409 коды — `not_found`, `method_not_allowed`, `conflict`,
а `details` — пустой список. В ошибках не возвращаются стек, пути исходников
и контекст исключения Pydantic.

## Демонстрация массового присвоения

В основном API нельзя передать `id`, `seller_id` или `user_id`: ответ 422.
В `app/vuln.py` намеренно оставлен отдельный пример из задачи 4:
обработчик принимает `dict` и выполняет `Product(**payload)`.
Так клиент может подменить продавца. Пример только возвращает модель,
не сохраняет её и не подключается к основному приложению.

Для сравнения запустить во втором терминале:

```bash
uv run uvicorn app.vuln:app --host 127.0.0.1 --port 8001
```
