# Каталог товаров

Сервис для покупателей и продавцов: каталог товаров по категориям, остатки
и отзывы. В первой лабораторной реализован HTTP-сервер
в трёх вариантах (последовательный, потоки и asyncio): проверка состояния, создание и удаление товара.
Данные хранятся в словаре и исчезают после остановки сервера.

## Предполагаемые сущности

| Сущность | Назначение | Ключевые поля | Связи |
|---|---|---|---|
| User | Покупатель или продавец | id, email, password_hash, role | владеет товарами, отзывами и заказами |
| Category | Категория каталога | id, name | объединяет товары |
| Product | Товар | id, seller_id, category_id, name, price, stock | принадлежит продавцу и категории, имеет отзывы |
| Review | Отзыв покупателя | id, user_id, product_id, rating, text | принадлежит пользователю и товару |
| Order | Заказ | id, user_id, status | принадлежит покупателю, содержит позиции |
| OrderItem | Позиция заказа | id, order_id, product_id, quantity, price | связывает заказ и товар |

Конкурирующий ресурс — ограниченный остаток товара на складе.
Правило: нельзя заказать больше единиц, чем осталось; успешный заказ
уменьшает остаток, который не может стать отрицательным.
Владельцы есть у товара, отзыва и заказа.
Это модель для следующих работ: в lab1 нет авторизации, базы данных,
отзывов и оформления заказов. Сервер только сохраняет и удаляет товары.

## Маршруты

| Метод и путь | Результат |
|---|---|
| `GET /health` | `200`: status, service, version |
| `POST /products` | `201`: переданный объект с новым числовым id; заголовок Location |
| `DELETE /products/{id}` | `204` без тела; для отсутствующего товара `404` |

Неизвестный путь возвращает `404`, неподдерживаемый метод — `405` с `Allow`,
некорректный JSON или запрос — `400`. Тело POST должно быть JSON-объектом.
Идентификатор назначает сервер. Остальные поля в этой работе не проверяются.
Сервер читает заголовки до пустой строки и дочитывает тело по `Content-Length`.
Поддерживается `Expect: 100-continue` для нагрузочного клиента задачи 5.
После ответа соединение закрывается.

## Запуск

Нужны Git, curl и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Python 3.13 устанавливается через uv.

```bash
git clone git@github.com:Alvald1/backend_labs.git
cd backend_labs
git switch lab-01
cd lab1
uv python install 3.13
uv sync --locked
uv run python -m rawhttp.server
```

По умолчанию сервер слушает `127.0.0.1:8000`. Если порт занят:

```bash
uv run python -m rawhttp.server --host 127.0.0.1 --port 18081
```

Во втором терминале:

```bash
curl -i http://127.0.0.1:8000/health
curl -i -X POST http://127.0.0.1:8000/products \
  -H 'Content-Type: application/json' \
  -d '{"name": "Keyboard", "category_id": 1, "price": 2500, "stock": 10}'
curl -i -X DELETE http://127.0.0.1:8000/products/1
```

Проверка кода из папки `lab1`:

```bash
uv run ruff check .
uv run ruff format --check .
```

Если сервер работает на другом порту, укажите его в командах curl.

Остановка сервера — `Ctrl+C` в его терминале.

### Дополнительные задания

Другие версии запускаются по одной, на том же свободном порту:

```bash
uv run python -m rawhttp.server_threads --port 18081
uv run python -m rawhttp.server_async --port 18081
```

У всех версий есть `--backlog`, по умолчанию 128.
Перед нагрузочным запуском в терминалах сервера и клиента:

```bash
ulimit -n 4096
```

Клиент открывает N соединений одновременно. Его таймаут охватывает
подключение и обмен, по умолчанию 30 секунд. В режиме `--delay` пауза
начинается только после получения `100 Continue` от сервера.

```bash
uv run python scripts/load.py 100 --port 18081
uv run python scripts/load.py 1000 --port 18081
uv run python scripts/load.py 50 --port 18081 --delay 0.2
```

Для контрольного прогона остановить выбранный сервер через `Ctrl+C`,
запустить его с `--backlog 4096` и повторить N=1000:

```bash
uv run python -m rawhttp.server --port 18081 --backlog 4096
```
